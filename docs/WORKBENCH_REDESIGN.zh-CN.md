# RoutePilot 专业工作台布局重设计实施方案

日期：2026-09-08。

状态：设计方向已确认；P0 基线与 P1 可点击原型已制作，见[原型与基线记录](WORKBENCH_PROTOTYPE.zh-CN.md)。原型等待用户确认；P2–P5 产品改造与最终验收尚未开始。

## 1. 问题与目标

上一轮完成了配色、字体、品牌和组件外观更新，但保留了左侧全局导航、顶部栏及主要页面的内容排列。用户指出，导航框架、每个路由页面的卡片排列和表格结构仍与原来基本一致，没有达到整体重设计的预期。

本轮目标是将界面重新组织为专业工作台：围绕运行监控与请求排障建立默认工作区，以顶部工作区导航配合局部导航，按每类任务重新分配页面空间和操作路径。

核心验收原则：**即使去掉颜色，仍能明显看出导航、内容结构和使用方式发生了变化。每个路由页面都要检查，不能只改首页。**

## 2. 已确认决策

| 决策 | 用户确认的方向 |
| --- | --- |
| 改动范围 | 允许调整导航位置、页面分组、内容排列和操作入口；功能保留，操作路径可以变化 |
| 产品气质 | 专业工作台，强调紧凑、高效和任务导向 |
| 默认任务 | 运行监控与排障优先；配置管理形成另一工作区 |
| 导航 | 顶部工作区导航 + 工作区内局部导航 |
| 详情交互 | 桌面优先列表、详情、操作同屏；日志采用列表与详情分栏，配置采用对象目录与编辑区域 |
| 视觉基础 | 保留当前配色、字体和 RoutePilot 品牌 |
| 信息层级 | 核心内容优先；低频统计、辅助说明和高级配置允许逐步展开，全部功能与数据仍可访问 |
| 实施顺序 | 先制作可点击原型，覆盖全局导航、运行概览、日志排障及一个配置页面；用户确认后扩展到全部路由页面 |

工作区名称、具体页面归属、分栏比例及配置原型选页属于下文的实施提案，通过原型验证，不冒充已经逐项确认的设计。

## 3. 与既有方案的关系及边界

[上一轮视觉重构方案](FRONTEND_REDESIGN.zh-CN.md)与其[验收记录](FRONTEND_REDESIGN_VALIDATION.zh-CN.md)继续保留为历史记录。其完成状态只适用于上一轮，不能作为本轮已经通过的证据。

本轮以本文取代旧方案中以下限制：保留侧栏尺寸与交互骨架、固定导航分组与入口、固定 Tab 和详情抽屉、禁止移动操作或增加展开步骤。现有表格、卡片及弹窗的位置和形式不再是必须保留的约束。

以下边界继续生效：

- 保留业务能力、字段、数据来源及统计口径；后端业务语义和权限保持不变。技术标识兼容约束已由全面改名计划取代，统一使用 RoutePilot 命名，不提供旧配置或数据兼容。
- 保留现有 URL 和直接访问能力，导航重组无需强制更名 URL。新增视图状态不得使旧链接失效。
- 数据获取和业务状态优先复用现有 hooks、services、stores，不借布局改造重构无关逻辑。确需调整界面状态时，检查选中项、筛选、分页、未保存编辑和账号切换行为。
- 完整遵循 [Dashboard 行为契约](../dashboard/README.md)：只读运行配置、估算及来源标记、权限拒绝、危险操作确认、Secret 引用和一次性密钥交接等语义不变。
- 次要说明可以展开，但估算、陈旧数据、权限限制、操作后果及当前字段必需说明必须在相关数据或操作处可见。
- 沿用现有技术栈、浅色/深色/跟随系统模式；不以本轮设计新增后端配置能力或虚构监控数据。

## 4. 信息架构提案

顶部只表达工作区切换，不把所有旧侧栏链接横向挤在一行。局部导航只显示当前工作区的页面；对象目录位于页面内容内，不另造一套全局侧栏。

| 建议工作区 | 现有路由 | 主要任务 |
| --- | --- | --- |
| 运行 | `/dashboard`、`/logs`、`/operations`、`/enterprise` | 判断运行情况、定位请求失败、处理事件、核查运行账本 |
| 配置 | `/models`、`/settings` | 管理 Provider、模型及现有路由能力，检查运行配置 |
| 访问与治理 | `/api-keys`、`/users`、`/quotas`、`/governance` | 管理访问边界、配额及变更审批 |
| 接入指南 | `/guide` | 从客户端配置走到请求验证，可作为独立辅助入口 |

账号、主题和会话操作保持容易找到。未授权页面不能因工作区聚合而暴露；没有可见页面的工作区不展示。局部导航与直接路由必须遵守同一权限策略。

默认进入运行概览；已有深链接仍直接打开目标页面。工作区切换不能隐式丢弃未保存表单或尚未完成的一次性密钥交接。

## 5. 逐路由页面改造要求

以下是原型和后续实现的起点。开始改造每页前须核对其全部现有字段、操作和状态；矩阵不是删减功能的清单。

| 页面 | 目标空间组织 | 必须验证的结构变化 |
| --- | --- | --- |
| 运行概览 `/dashboard` | 紧凑运行摘要与时间范围；主区呈现关键趋势和运行情况，旁区集中异常及排障入口；低频统计按主题展开 | 不再按原顺序堆叠指标卡、图表和快捷操作；首屏能回答是否正常及下一步查看哪里 |
| 请求日志 `/logs` | 筛选工具区 + 请求列表 + 常驻详情区；选中请求即更新详情 | 将“表格后打开抽屉”改为连续排查工作流；调整列表字段优先级、列宽及摘要结构，不能只把旧抽屉固定在旁边 |
| 运维事件 `/operations` | 事件队列 + 事件处理区域，关联事实、响应操作和时间线 | 围绕选中事件处理，不再先浏览成排指标卡再向下找事件；复用已有分栏时也须重新组织内部层级 |
| 运行账本 `/enterprise` | 请求账本与详情联动；预算控制、账务调整、证据事件放入清晰局部分区 | 减少异质模块纵向混排，保留现有账本和控制能力及说明 |
| 模型与渠道 `/models` | Provider/模型对象目录 + 选中对象的配置与检查区域；现有默认路由和别名能力融入相关上下文 | 替换重复 Provider 卡片堆叠，形成对象选择、检查、编辑的连续流程 |
| 运行设置 `/settings` | 设置分类目录 + 配置事实阅读区 + 对应运维操作区 | 替换通用横向 Tab 加卡片堆叠；明确只读事实和可执行操作 |
| API 密钥 `/api-keys` | 密钥目录/列表 + 选中密钥的权限、限制、接入与生命周期操作 | 重组选择、检查、编辑路径；一次性明文交接维持独立且明确的完成步骤 |
| 用户 `/users` | 用户目录 + 用户上下文区域，关联当前用户的密钥和可执行管理操作 | 从通用表格加弹窗转为围绕对象管理；避免出现多层并列导航 |
| 配额 `/quotas` | 配额对象列表及状态摘要 + 规则编辑与用量解释区 | 重点呈现受限对象与原因，不以顶部指标卡为主体；不同单位不能混合相加 |
| 治理 `/governance` | 审批任务列表 + 变更详情及审批区域；队列与治理状态作为辅助区域 | 突出待处理任务、变更内容和后果；保留权限及审批门禁 |
| 使用指南 `/guide` | 步骤目录 + 当前接入步骤 + 对应代码示例与验证指引 | 由长页模块改成可逐步完成的接入流程，保留真实模型目录和权限约束 |
| 登录 `/login` | 围绕认证主任务重新构图，品牌说明与登录表单建立新的空间关系 | 不套用工作台导航，也不只替换表单装饰；保留现有认证入口 |
| 未找到页面 `*` | 简洁的定位说明与有效返回入口 | 与新工作区衔接，避免死路；拒绝访问状态与不存在页面仍有区别 |

表格仍可用于需要横向比较的数据。验收看列组织、主次关系、详情联动和操作路径是否重新设计，不要求为了差异强行将全部表格改成卡片。

## 6. 原型范围与交互要求

首先制作四类可点击原型：全局导航、运行概览、请求日志、模型与渠道配置页。配置页选择 `/models` 是实施提案，用于验证对象目录与编辑区域。

原型须支持：

1. 切换顶部工作区，看到对应局部导航和当前位置。
2. 在概览判断运行情况，并进入日志排查；仅在数据与筛选能力支持时携带相关上下文。
3. 筛选请求、选择列表项、切换详情、展开次要信息和返回列表。
4. 选择 Provider/模型、进入编辑并演示保存或取消；模拟操作必须明确标注，不进行真实写入。
5. 展示正常、无数据、异常及受限状态的代表场景，避免只展示理想数据。
6. 在桌面和窄屏切换结构：窄屏采用列表到详情的单栏路径，并提供明确返回入口，保留选择与筛选上下文。

复用现有主题，使用明确标记的演示数据。原型结果不等同于真实后端或上游验证。需要展示尚无实现的页面时明确标记为结构占位，不声称已完成。

提交原型时附同视口、同数据场景下的新旧对照，重点解释导航、区域分配、信息优先级和操作路径的变化。原型通过后才扩展全页面实施；这一节点来自用户已接受的实施顺序。

## 7. 实施阶段与交付物

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| P0 基线与清单 | 记录当前提交、各路由截图、角色可见性、字段/操作/状态清单；核对本文提案与实际能力 | 每个路由可追踪，已知限制记录完整 |
| P1 可点击原型 | 实现第 6 节四类原型及代表性窄屏视图 | 原型可操作，结构差异可对比，提交用户确认 |
| P2 工作台框架 | 在确认后的结构上实现顶部导航、局部导航、页面容器及响应式切换 | 所有旧路由可达，权限与浏览器前进后退正常 |
| P3 核心页面 | 改造概览、日志、模型配置，接回真实数据及操作 | 完成监控、排障、配置主流程，行为契约通过 |
| P4 全页面扩展 | 逐一实施第 5 节其余页面，包括登录、指南和异常状态 | 每个路由单独验收，原布局残留逐项处理 |
| P5 验收与记录 | 执行结构、交互、权限、响应式与必要回归检查 | 形成独立本轮验收记录，区分通过、失败、未验证和环境限制 |

先完成 P0/P1，不提前将全部产品页面改造成未经原型确认的结构。具体组件命名、尺寸和断点在原型中确定；共享框架统一导航、工具区和分栏行为，各页保留任务所需的布局差异。

## 8. 验收标准

### 8.1 结构与体验

- [ ] 全局导航已由贯穿所有页面的左侧菜单改为顶部工作区与局部导航。
- [ ] 原型四类页面已得到用户确认，并记录确认范围与后续调整。
- [ ] 第 5 节每个路由均有改造前后对照、结构变化说明和功能去向清单。
- [ ] 隐去配色后仍能从结构看出变化；仅改间距、边框或移动一两张卡片不算完成。
- [ ] 概览首屏突出运行情况和排障入口，次要模块不抢占主任务空间。
- [ ] 日志能够连续选择请求并同屏阅读详情；配置能够选择对象并在上下文中检查和编辑。
- [ ] 低频内容可找到、可展开；关键事实和操作后果没有被折叠隐藏。
- [ ] 所有功能和字段都有新位置，操作入口清晰；不存在只有首页重设计、其余页面沿用旧结构的情况。

### 8.2 行为与适配

- [ ] 角色导航、直接访问权限、账号切换和查询缓存隔离保持正确。
- [ ] 筛选、分页、选中项、浏览器前进后退及未保存编辑行为经过验证。
- [ ] 表单提交、取消、确认、错误恢复以及一次性密钥展示与离开保护仍有效。
- [ ] 加载、刷新、陈旧数据、失败、空结果、拒绝访问等状态可区分。
- [ ] 日志虚拟列表的尺寸与实际行高一致，选中详情不会错位或串到其他请求。
- [ ] 浅色、深色和跟随系统均可用；常规桌面、窄桌面及 390 CSS 像素窄屏完成检查。
- [ ] 窄屏主流程无页面级横向滚动；分栏转单栏后仍可完成任务。
- [ ] 导航、列表选择、详情和表单可用键盘操作，焦点流转与返回位置合理。

### 8.3 验证与证据

按 [开发说明](DEVELOPMENT.md)和 Dashboard 行为契约选择检查。实现阶段运行前端 `npm run check`，对导航、分栏选择、编辑及权限变化更新并执行相关 E2E；最终检查覆盖所有受影响的主要工作流。只有新增修改、失败或未解决风险才扩大或重复检查。

本轮验收记录应包含提交与环境、各路由前后截图、工作流结果、演示/真实后端数据来源、未验证项和复现说明。上一轮测试结果不能替代本轮验证，演示预览不能作为真实上游可用性证据。
